# Summary

The goal of lexical analysis is:
- get rid of semantically irrelevant information (e.g. whitespace, syntax of keywords...)
- give a rough classification (simplification) of the input to simplify the next stage (parsing)
  - identify the lexical structure and tokens of the language
  - partition the input string into small units (tokens) used by the parser
  
lexing scans the input string left-to-right, sometimes with lookahead.


# Tasks for the lexical stage

The point of the lexical phase is 
1. **Description** of the lexical structure of the language (determination of the token classes)
   We use **regular expressions** for this purpose.
2. From the description in (1), derive a scanning **algorithm** called a **lexer**, that determines the token class of ech lexical unit.
   We use FSAa (**finite state automata**) for this.
   
# Regular Expressions

**Regular Expressions** (REs) are a way of precisely describing the set of lexemes (strings) associated with each token.

Informally, with REs we can say something like this: an integer is a non-empty string of digits.

But we want to be more precise than using natural language.

The real point of REs is to enable a **precise** description of languages that are too **large** to enumerate.

Let *A* be an alphabet, i.e. a set of characters. We now define two things in parallel:
- The **regular expressions**** (aka REs or regexes) over A.
- The **language of** (aka **language denoted** or **generated by**) each regex over *A*. The language of a regex *R* is noted by lang(*R*).

In short, a regex is a pattern that describes a set of strings. You give it a string, and it either matches or it doesn't.

Alphabet {0,1} means strings can only contain the characters 0 and 1. 0 matches the string 0, and 01 matches the string 01, and nothing else.

| means either this or that. 0|1 matches either 0 or 1. those are the only two strings it matches. (0|1) is the same things.

- 0(0|1) means 01 or 01.

* means repeat the things before me any number of times, including 0 times. 0* means blank, 0, 00, 000, and so on. (0|1) matches any strong of 0s and 1s including the empty on. each repeat picks a 0 or a 1 freely.

01* means 0, 01, 011, 0111, and so on.
(01)* means blank, 01, 0101, 010101, etc.

# The essential definitions for Regular Expressions

- **Alphabet**: a usually finite set of characters.
  - e.g. {1,4,7}, {a,b,..,z}
- **String**: aka **word**, OVER AN ALPHABET a finite sequence of elements from A.
  - "welcometocompilers" uses alphabet {a,b,...,z}
  
If whitespace is not included in the alphabet, then a sentence like the one you're reading is not in the alphabet.

The only string over the empty alphebet is ""

- **Language**: OVER AN ALPHABET is a set of strings over A. Examples over {a,b,..,z} include:
  - "" empty language
  - {""}
  - {"welcometocompilers"}
  - {"welcometocompilers","dontforgettodotheexcercises"}
  - the set of all strings of even length over {a,b,..,z}
  - the set of all strings over {x,y} with as many 'x's as 'y'scanning
  
  The languages are infinite
  
# Specifying Languages

*Finite* languages: consisting of a finite number of strings.
- these can be given by listing all strings

*Infinite* languages: not possibly to be given by listing all strings.

*Regular expressions* are a mechanism to specify finite and infinite languages.

- A finite state automata (FSA) is an algorithm that, given a string over an alphabet (all), answers with TRUE or FALSE

- The set of strings that the FSA says TRUE to is the **language recognised** by the FSA. FASa *decide* languages.

- A word w is accepted by an FSA if there is a path line in the FSA such that:
  - it starts at the initial state and ends at the terminal state
  - the edge labels on this path spell the word w
  
A *transition* or edge is to be understood as:
    - if the automaton is in state s and *reads* (consumes/eats) the character a, then it moves to state terminal
    
If, starting from the initial state an readin the input string following the tranditions, we reach the *end* the input in a *terminal* state:
    - the input string is *accepted*, and is in the end of the automaton
    
If, we cannot find the path from the initial state to a terminal state, which matches the whole input string:
    - the inpur string is rejected, it is *not* in the language of the automaton


A finite state automaton (FSA or FA) is a tuple
A = (Σ, S, i, F , R) such that:
▶ Σ is a finite set (the alphabet of the automaton)
▶ S̸ = ∅ is a finite set (the set of states of the automaton)
▶ i ∈ S (the initial/start state of the automaton).
▶ F ⊆ S (the set of terminal/accepting/final states)
▶ R ⊆ S × Σ × S (the transition relation of the automaton)


The FSA A is deterministic (a DFA) if for each pair of state
s ∈ S and character α ∈ Σ, there is at most one transition
s α
−→ t, to any state t.
Otherwise A is non-deterministic (a NFA); i.e., from at least
one state there are two or more outgoing arrows labeled with
the same character. 

## Accepting a string

A string (α1, . . . , αn) over the alphabet Σ is accepted by the automaton A = (Σ, S, i, F , R) if there is a path of transitions

The **language** of (or **recognised** by) an automaton A is the set of all accepted strings.We write lang(A) for this language.
